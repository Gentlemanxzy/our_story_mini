# 数据库安全规则

四个集合都在 **云开发控制台 → 数据库 → 选中集合 → 权限设置 → 自定义安全规则** 里粘贴。

---

## 现阶段：客户端一律不直连

当前所有读写都经过云函数（管理端权限，不受安全规则限制），客户端不需要直连数据库。所以四个集合统一收紧为：

```json
{
  "read": false,
  "write": false
}
```

适用于：`things`、`categories`、`couples`、`users`。

### 为什么这样定

1. **云开发没有「指定两个人共写」这种预设权限**，靠预设规则做不到双方共编。
2. **写入必须经过服务端校验**。若放开客户端写，用户可伪造 `coupleId` 把自己塞进别人的空间。
3. 本期还没做实时同步，客户端直读没有收益，收紧更安全。

云函数写入时已按当前作用域写好 `members` 字段（单人空间是 `[自己]`，绑定后是双方），所以将来切换成客户端直读只需改规则、不用改数据。

---

## 将来做实时同步（`db.watch()`）时怎么改

`watch()` 走的是**客户端数据库权限**，那时必须放开读：

`things` 与 `categories`：

```json
{
  "read": "auth.openid in doc.members",
  "write": false
}
```

- 规则无法跨集合查询，所以 `members` 必须冗余存在每条文档上（云函数已经这么写了）。
- 绑定成功时，`couple_join` 需要**级联补齐**该 `coupleId` 下所有 `things` / `categories` 的 `members`，否则加入方看不到已有数据。
- 若 `in` 在你的环境不生效，等价写法：`doc.members.indexOf(auth.openid) > -1`。
- 切换后**必须用两个真实微信号各测一次**：A 号不应读到 B 号的私人数据。

`write` 始终保持 `false`——写入继续走云函数。

## 建议索引

| 集合 | 索引字段 | 说明 |
|---|---|---|
| `things` | `coupleId` + `order` | 清单按序拉取（`sync_pull` 用到） |
| `things` | `coupleId` + `status` | 章节页统计 |
| `categories` | `coupleId` + `order` | 分类按序展示 |

**不要给 `couples.code` 建唯一索引**：唯一索引下缺失字段视为 `null`，全集合最多只能有一条无 `code` 记录；且绑定后把 `code` 置空会冲突。唯一性由 `couple_create` 云函数在事务内「查重 → 插入」保证。
